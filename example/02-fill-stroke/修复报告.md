# 02-fill-stroke 修复报告

针对 `example/02-fill-stroke/` 下填充与描边 fixture 的多处渲染缺陷,已在 `src/` 中完成修复并通过全部回归用例。

---

## 修复 1 — `02-stroke-styles.svg` panel 3 / panel 7:`stroke-linecap` 不生效

### 现象

```xml
<!-- panel 3 -->
<line ... stroke-width="10" stroke-linecap="butt"/>
<line ... stroke-width="10" stroke-linecap="round"/>
<line ... stroke-width="10" stroke-linecap="square"/>

<!-- panel 7 -->
<path ... stroke-linecap="round" stroke-linejoin="round"/>
```

期望:三种端点形态(平头 / 圆头 / 方头)肉眼可辨。
实际:三条线端点完全一致(全部平头),`round` / `square` 无效。

### 根因

pptxgenjs 在生成 `<a:ln>` 元素时硬编码了写入逻辑,**完全没有暴露 `cap` 属性**:

```xml
<!-- pptxgenjs 写出的 -->
<a:ln w="..."><a:solidFill .../></a:ln>
```

而 DrawingML 的端点形态由 `<a:ln cap="flat|rnd|sq">` 控制。从 SIF 层传 `lineCap` 也无处可写。

---

## 修复 2 — `02-stroke-styles.svg` panel 4 / panel 7:`stroke-linejoin` 不生效

### 现象

panel 4:三角形拐点的 `miter`、`round` 无区别(全部直接是尖角)。
panel 7:`round` 与 `miter` 的拐点也没有差别。

### 根因

同上,pptxgenjs 写出的 `<a:ln>` 没有包含 join 子元素。
DrawingML 中:`miter` 是默认值不写;`round` 需要 `<a:round/>`;`bevel` 需要 `<a:bevel/>`。

---

### 修复 1 + 2 — 统一方案:.pptx XML 后处理

由于 pptxgenjs 在高层 API 上 **无法表达** `cap` 与 join,我们在打包完成后对生成的 `.pptx` 做一次 XML 后处理:

新文件 `src/pptx/utils/post-process.ts`:

```ts
export interface PptxPostProcessHint {
  cap?: 'flat' | 'rnd' | 'sq'
  join?: 'round' | 'bevel' | 'miter'
  fillRule?: 'nonzero' | 'evenOdd'   // 供修复 3 复用
}

export async function postProcessPptxBuffer(
  buffer: Uint8Array,
  hintsPerSlide: PptxPostProcessSlideHints[]
): Promise<Uint8Array>
```

实现要点:
1. 用 JSZip 打开 .pptx,遍历每张 `ppt/slides/slideN.xml`。
2. 按文档顺序扫描 `<a:ln>...</a:ln>` 与 `<a:custGeom>...</a:custGeom>` 块。
3. 每个 `<a:ln>` 块按顺序消费一条 **line hint**:
   - 写入 / 替换 `cap="..."` 属性;
   - 在 `</a:ln>` 前注入 `<a:round/>` 或 `<a:bevel/>`(`miter` 不需注入)。
4. 每个 `<a:custGeom>` 块按顺序消费一条 **geom hint**(见修复 3)。

`<a:ln>` 与 `<a:custGeom>` 计数器 **独立**,因为同一个形状可能只产出其一(无描边的自定义路径只有 `custGeom`、纯描边矩形只有 `<a:ln>`)。

### 生成器侧 — `src/pptx/generator.ts`

收集每个形状的 `{lineHint, geomHint}` 片段,按形状被加入幻灯片的顺序入队;只有 `data.shapeName === 'custGeom'` 时才入 `geomHints`,避免对内置预设形状(`rect` / `ellipse` 等)误注入 `fillRule`。

```ts
this.pushHint(h.lineHint, h.geomHint, /*emitsLine*/ true,
              /*emitsCustGeom*/ data.shapeName === 'custGeom')
```

`writeBuffer()` / `writeFile()` 统一在最后调用 `postProcessPptxBuffer()`,确保所有写出路径都经过后处理。

### 验证

- panel 3:三条线分别显示平头 / 圆头 / 方头。
- panel 4:`miter` 拐点尖、`round` 拐点圆。
- panel 7:`round + dasharray` 组合下端点为圆,拐点为圆;对比组 `butt + miter` 端点平、拐点尖。

## 修复 3 — `03-fill-rule.svg` panel 2 / 4:`fill-rule="evenodd"` 不生效

涉及两条独立 bug,合并在同一处叙述。

### Bug A — `<a:custGeom>` 缺 `fillRule` 属性

#### 现象
panel 2(五角星 evenodd)与 panel 4(同心圆 evenodd)与对应的 nonzero 版本视觉一致,无镂空效果。

#### 根因
pptxgenjs 写出的 `<a:custGeom>` 不带 `fillRule` 属性,DrawingML 默认按 `nonzero` 解释:

```xml
<a:custGeom>...</a:custGeom>   <!-- 缺 fillRule -->
```

#### 修复
复用 **修复 1 + 2** 的 XML 后处理通道。SIF → PPTX 转换时,如果路径携带 `fillRule: 'evenodd'`,就生成 `geomHint = { fillRule: 'evenOdd' }`(注意 PPTX 的大小写是 `evenOdd`)。后处理器把它写入对应的 `<a:custGeom fillRule="evenOdd">`。

修复后 XML:

```xml
<a:custGeom fillRule="evenOdd">
  <a:pathLst>
    <a:path w="..." h="...">
      <a:moveTo>...</a:moveTo>
      <a:arcTo .../>
      ...
    </a:path>
  </a:pathLst>
</a:custGeom>
```

### Bug B — panel 3 / panel 4 同心圆环坍缩成单圈

修复完 Bug A 后,panel 2 五角星正确镂空,但 panel 3、panel 4 的同心圆 **仍然渲染错误**:外圈和内圈被拼成一个变形闭合区域,evenodd 无法"挖洞"。

#### 现象

`<a:custGeom fillRule="evenOdd">` 已正确写入,但内部路径数据 **缺第二个 `<a:moveTo>`**:

```xml
<a:moveTo>(571495, 142586)</a:moveTo>
<a:arcTo swAng="-21599943"/>   <!-- 外圈 -->
<a:close/>
<a:arcTo swAng="18000000"/>    <!-- 内圈,无 moveTo!直接从外圈起点拉过来 -->
<a:close/>
```

#### 根因

`src/svg/utils/path-parser.ts` 的 `Z` 命令处理在 `i` 上 **多递增了一次**:

```ts
// 旧代码
case 'Z': {
  points.push({ close: true, type: 'Z' })
  current = { ...subpathStart }
  i++  // ← 多余:外层 while 已经做过 i++
  break
}
```

外层 while 在进入 switch **之前** 就已经 `i++` 跳过了 `Z` token。`case 'Z'` 里再 `i++` 会跳过紧接 `Z` 的下一个 token —— 对 donut 路径来说,被吞掉的正是 `M 120 110`。

对 `M 120 80 ... Z M 120 110 ... Z` 这种"闭合 + 立刻开启新子路径"的写法(`donut.svg` 用了它),第二个 `M` 被解析器静默丢弃。后续的相对弧线 `a 30 30 0 1 1 -0.001 0` 以外圈起点 `(120, 80)` 为当前点起算,把内圈的整段路径错位到了外圈起点,evenodd 无法把它当独立子路径处理。

#### 修复

`src/svg/utils/path-parser.ts`:删除 `Z` case 里多余的 `i++`,并加注释解释为什么不能再加。

```ts
case 'Z': {
  // 外层 while 已经把 i 推过了 `Z`;Z 没有参数,绝对不能再 ++。
  // 此前漏掉这一点,导致 donut/evenodd 形状把内圈 `M` 吞掉。
  points.push({ close: true, type: 'Z' })
  current = { ...subpathStart }
  break
}
```

#### 验证

修复后 panel 4 的 XML:

```xml
<a:custGeom fillRule="evenOdd">
  <a:moveTo>(571500, 571500)</a:moveTo>
  <a:arcTo swAng="-21599943"/>    <!-- 外圈,顺时针 -->
  <a:close/>
  <a:moveTo>(571500, 857250)</a:moveTo>  <!-- ✓ 内圈独立 moveTo -->
  <a:arcTo swAng="21599885"/>     <!-- 内圈,逆时针(方向相反) -->
  <a:close/>
</a:custGeom>
```

panel 3(nonzero,但两个子路径绕向相反)与 panel 4(evenodd)在 PowerPoint 中均正确显示为环形。

## 修复 4 — `04-none-fill.svg` panel 1:`fill="none"` 矩形丢失虚线

### 现象

```xml
<rect ... fill="none" stroke="#E74C3C" stroke-width="3" stroke-dasharray="6 4"/>
```

## 修复 5 — `04-none-fill.svg` panel 6:`OUTLINE` 描边文字实心填充

### 现象

```xml
<text ... fill="none" stroke="#2C3E50" stroke-width="1.5">OUTLINE</text>
```

期望:仅有深色描边的空心字。
实际:文字被填成 **纯黑实心**,既无描边也看不出 `fill="none"`。

### 根因

两个问题叠加:

#### 5a — SIF 文本元素没有 `stroke` 字段

`TextElement` / `RichTextElement` 只有 `fill: Fill`,完全不承载 `stroke`。SVG 解析时拿不到对应字段,PPTX 转换时也就无从写出文字描边。

#### 5b — pptxgenjs 文本永远写 `<a:solidFill>`

即便 SIF 端把 `fill.type` 设为 `'none'`,pptxgenjs 在文本运行 `<a:rPr>` 里始终会写入一个 `<a:solidFill val="..."/>`,无法表达"无填充"。`color: undefined` 不能让它跳过。

### 修复

#### 5a 修复:让 SIF 文本携带描边

`src/sif/types/elements/text.ts`:`TextElement` 和 `RichTextElement` 各新增 `stroke?: Stroke`。

```ts
export interface TextElement extends BaseElement {
  type: 'text'
  ...
  fill: Fill
  stroke?: Stroke   // SVG 允许 <text>/<tspan> 上有 stroke
  ...
}
```

`src/svg/converters/text.ts`:从 SVG `<text>` 上用 `extractStroke()` 提取描边,写入 SIF 节点(plain text 与 rich text 两条路径都写)。

#### 5b 修复:在 PPTX 端伪造"透明 fill + outline"

`src/pptx/converters/text.ts`:

1. 当 `text.fill.type === 'none'` 时,把颜色设为 `'000000'` + `transparency: 100`,让 pptxgenjs 生成 `<a:alpha val="0"/>`(视觉上看不见):

   ```ts
   ...(text.fill.type === 'none'
     ? { color: '000000', transparency: 100 }
     : { color: convertTextFill(text.fill) }),
   ```

2. 当 `text.stroke` 存在时,通过 pptxgenjs 暴露的 `outline: { color, size }` API 写入文字描边(对应 `<a:rPr><a:ln/></a:rPr>`):

   ```ts
   if (text.stroke) {
     const outlineColor = convertStrokeOutlineColor(text.stroke)
     if (outlineColor) {
       const widthPt = Math.max(0.25, (text.stroke.width || 1) * PX_TO_PT)
       textOptions.outline = { color: outlineColor, size: widthPt }
     }
   }
   ```

### 验证

panel 6 的 `OUTLINE` 文字现在显示为仅有深色描边的空心字。
